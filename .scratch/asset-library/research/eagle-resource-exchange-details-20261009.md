# Eagle 精选资源取得与素材包交换：细节依据

调查日期：2026-10-09（Asia/Shanghai）。研究票 **49**，服务于人工决策 **38 — 精选资源与素材包交换的产品契约**。

本轮沿用 [46 生态复核](eagle-ecosystem-audit.md)，只补充目录、资源取得和素材包交换的依据。研究代理使用 research、agent-reach 的网页读取路线及 web 工具；没有操作本地 Eagle，没有下载素材或实际导入／导出素材包。本文不改变用户决定，不定义本产品包格式，不把厂商声明当作实测。

## 1. 结论与证据层次

**Eagle 的资源目录既有可下载素材包，也有仅打开外部来源的条目；素材包可以携带文件、整理信息和文件夹层级。** 这些足以支持本产品讨论“发现 → 取得 → 入库”和“选择内容 → 导出 → 另一资源库导入”的完整产品流程，尚不足以确定重复导入、范围外关系、隐私字段和异常恢复规则。[资源目录][directory]、[包打开说明][open-pack]、[导入／导出说明][pack]

必须保留以下证据分层：

- **当前网页事实**：本轮读到的官方社区页面与帮助正文；字段与入口描述不代表实际下载、完整性或导入结果已经验证。
- **主代理现场观察**：本轮本地 Eagle 测试库中可见的入口、保存表单以及取消结果，单列于第 5 节；研究代理未操作。
- **正文不可得**：只得到标题／站点外框的帮助文章，不能凭问题标题推定回答。第 8 节记录具体 URL。
- **建议与待选契约**：第 7 节为推导，须由用户回答后写入决策；不因竞品已有类似功能而自动采纳。

## 2. 目录分类、版权与取得方式

### 2.1 目录实际公开了哪些维度

[英文资源目录][directory]当前可见：

| 维度 | 本轮可见内容 | 事实边界 |
| --- | --- | --- |
| 领域 | UI 设计、平面设计、插画、游戏、室内、工业 | 是当前可见领域，不是本产品已选分类 |
| 类别 | 图标、插画、概念设计、字体、UI、样机等 | 初始页面可见示例，不宣称完整分类全集 |
| 内容类型 | 灵感、素材 | 灵感参考与可用于作品的素材需在详情区分 |
| 版权筛选 | Royalty Free、Non-Commercial | 是目录标签，不替代逐项核验来源许可；Royalty Free 不宜直接翻译成“无版权” |
| 格式筛选 | 仅显示 eaglepack | 说明目录不只有 Eaglepack 条目 |
| 发现与排序 | 搜索；最近、最早、浏览、下载、喜欢、精选等排序 | 不由这些入口推定账号、下载权限或完整服务契约 |

### 2.2 两种明确不同的资源入口

| 官方样本 | 本轮读到的类型与入口 | 可成立的判断 |
| --- | --- | --- |
| [3D Icons][icons] | 类型 Eaglepack；有下载及独立的来源访问入口，来源为 3dicons.co；显示贡献者、更新时间、版权、分类 | 下载包与访问来源是两个动作；看到来源链接不等于已经取得文件 |
| [Blender Kit][blender] | 类型 Resource Link；主要动作 Open 指向 blenderkit.com；显示版权和分类 | 目录可以只介绍外部资源；本轮页面没有读取到 Eaglepack 直接下载入口 |

本轮没有点下载、没有跟随素材来源完成取件，也没有建立本产品资源目录。能确认 Eagle 目录同时容纳“包”和“外部链接”；**不能由此确认普通文件的直接下载交付、外部站点账号条件、后续跳转或下载完成后的自动入库行为**。

### 2.3 `recent-design-og-images` 的中英文证据有差异

当前[英文详情][recent-en]顶部显示 **Resource Link + Open**，正文仍称其为 eaglepack；同时列出 3 MB、53 项、2026-09-29 更新，以及非商业用途。正文要求仅作设计参考，不得直接使用或修改后用于项目。入口类型与正文用语不能合并成一个已经确认的下载契约。

主代理在同日、本地 Eagle 内嵌的[中文详情][recent-cn]观察到 **Eaglepack 素材包 + 下载资源 + 查看素材来源**，容量、数量与更新时间一致，版权提示禁止商业使用，正文同样限制直接／修改后用于项目。未下载。两边差异原因未确认，不能自行解释成缓存、语言版本差异或条目刚更新，也不能选择其中一端抹掉另一端证据。

**评估：**本产品详情需要用明确的取得方式和许可说明兑现按钮含义。此建议源于上述差异，不是对本产品“是否仅提供直接取得资源”的代答。

### 2.4 目录标签不能成为再分发授权

[社区条款][terms]对站点内容的使用有单独限制，包括把站点内容用于竞争素材工具／资源库，以及自动化下载。已有“由本产品自行组织并具备相应权限的资源”方向不应被理解为可直接搬运 Eagle 目录。此处只记录官方条款，不替具体资源判断授权，也没有批量取得社区素材或下载素材文件。

## 3. 导出对象、文件夹和字段：可以确认到哪里

[官方导入／导出正文][pack]说明：素材可通过 Eaglepack 交换，标签会保留但标签组不保留；按文件夹导出／导入可保留原有分类与层级。操作是对文件夹或素材使用导出素材包，填写文件名和路径并保存；导入支持双击包后确认导入，或拖入 Eagle。

| 数据／范围 | 明确依据 | 不能顺带推定的行为 |
| --- | --- | --- |
| 文件本体及随附数据 | [不完整包排查][incomplete]要求检查包内原始文件、缩略图、metadata.json，以及包级 pack.json | 这不是规范化格式说明；不证明所有格式、缓存或多版本都被完整打包 |
| 标签与标签组 | [导入／导出说明][pack]明确标签保留、标签组排除 | 同名标签合并、层级映射、跨库身份和重导入策略未说明 |
| 文件夹层级 | 按文件夹交换可保留分类与层级。[同上][pack] | 多个导出根的公共祖先、空文件夹、智能文件夹及仅导出所选素材的归属范围未说明 |
| 标题、来源网址、标注与备注 | [包打开说明][open-pack]列出类别、标签、标题、URL、markups、notes 等携带内容 | 不代表与本产品“名称／注释／备注”的字段逐一相同，也不证明默认隐私开关或可逐字段选择 |
| 图片注释／评论 | 官方较早的[效率技巧文章][tips]第 11 项说明将整个文件夹打成包时，图片评论可一并保留 | 不能据此断言个人注释会被提示、默认排除，或所有版本均有同样 UI |
| 多归属与包外关联 | 本轮未取得明确的打包范围规则 | 不能从“保留层级”推定导出所有归属；也不能推定一个文件在两个文件夹中会复制为两份素材或保留为一条 |
| 评分、各类时间、授权记录、智能文件夹定义 | 本轮正文没有逐字段明确列出 | “等信息”不足以证明这些字段都会保留，更不构成本产品的默认导出清单 |

帮助文档将 Eaglepack 用于分享给另一位 Eagle 用户，也提到可用于保存资源库部分素材。[导入／导出说明][pack]这没有定义整库一致性、数据库恢复、备份点或灾难恢复，不能把资源包交换等同于完整备份恢复。

## 6. 与本产品已有范围的关系

以下是复用现有研究和主决策上下文的范围边界，不是本轮新增决定：本产品使用自己的资源包规范；Eaglepack 直接兼容后置；支持选中素材或文件夹导出供另一资源库导入；访问目录不自动上传个人资源库；资源交换不替代备份，也不包含自动发布社区。

**“收集包”与“资源包”的关系仍需产品定义。** Eagle 的 Eaglepack 文档只证明其交换能力，不能证明本产品既有收集包可以直接更名、共用全部字段或共用同一导入行为。可以提出共用包校验／文件取得等能力的候选，但如何处理来源、授权、归属和私人信息，应先形成使用者可理解的契约，再交模块设计。

本报告不重新选择 Rust、Tauri、界面库、数据库、压缩格式或传输协议；也不利用精选资源功能悄悄增加云端个人资源库、公开投稿、支付或原件替换。

## 7. 留给人工决策与工作台原型的问题

下列均为**待选建议／待明确问题**，不写成已确认验收条件。首批内容、提供者及目录是否只放可直接取得条目，主代理正在向用户确认；本研究不重复代答。

| 应形成的产品答案 | 可用于对照的具体场景 |
| --- | --- |
| 取得前展示什么许可与来源信息；不适合商用的内容怎样区分；何时需要确认 | 一份可再分发素材与一份只允许灵感参考的内容，按钮与入库结果应清楚不同；不能只靠一个“免费”标签 |
| 下载完成与入库完成怎样分别表达；取得位置和归属何时选择 | 下载成功后目标盘离线；用户能看到文件已取得而资源库尚未完成登记 |
| 导出素材／文件夹的确定范围，多归属与包外关系怎样裁剪 | 一个素材同时属于“项目 A”和“灵感”，仅导出“项目 A”，预览包中将出现的目录与关系 |
| 哪些字段必带、可选或排除；原文件内嵌信息是否保持原样 | 标签、来源网址、用户个人注释、评分、时间与授权各有明确规则；“不导出个人注释”不能被误解成已清除原文件 EXIF |
| 普通文件、资源包、收集包怎样区分用途与携带能力 | 同一选择既可交给系统文件夹，也可交给另一资源库；用户在提交前能识别整理信息是否随行 |
| 重新导入与后续版本怎样保护原有整理 | 同一包导入第二次；随后提供了同一资源的新版本，而用户已改名、添加私人备注 |
| 原件离线或部分取得失败时能否形成部分结果 | 10 项中 2 项原件不可用，用户应先理解实际会得到几项与缺失原因；是否允许跳过由用户裁定 |
| 取消、损坏和恢复的边界 | 下载一半取消、导入一半退出、导出空间不足各自显示何种状态；不能把三个阶段混成统一成功或失败 |
