# Eagle 图片比较与属性检查器的显示细节依据

调查日期：2026-10-09（Asia/Shanghai）。对应研究票：**48 — Eagle 图片比较与属性检查器的显示细节依据**。

用户已确认本产品首批三个只读插件为媒体信息、照片信息、两张图片比较；本报告只补第一方事实及显示细节的缺口，不重新选择插件，也不替用户决定显示规则。没有操作 UI、安装／运行插件或下载插件代码包。

## 1. 结论与证据等级

官方资料可以确认：图片比较有并排、分割、叠加三类模式；媒体信息和照片信息集成在右侧检查器，分别展示若干音视频参数和拍摄参数。**不能确认的重点仍包括：比较器最大图片数量、默认模式、不同尺寸的对齐／等比／裁剪／拉伸规则、缩放和平移联动、插件逐格式支持矩阵、EXIF 方向及 ICC／HDR 色彩处理。**

这些未知不否定本产品已经选择的两张图片比较或只读检查器。它们说明下一轮应给用户具体显示方案，再由本产品原型验证；不能把“Eagle 应该如此”当成已确认产品要求或实测能力。

证据分层：

- **官方目录事实**：三个详情页的发布者均为 Eagle App，正文与版本记录可读取；这是发布者说明，不是实际安装运行结果。[比较器][S1]、[媒体信息][S2]、[照片信息][S3]
- **官方补充介绍**：Eagle 4 发布文章及 Plugin API 检查器文档补充字段和扩展形态；通用示例不是这三个插件的具体实现。[Eagle 4 发布介绍][S4]、[检查器文档][S5]
- **图片证据限制**：三个目录及发布介绍均带官方宣传图片。本轮 web 读取图片链接只返回资源地址，未取得可检查的像素／控件文本，不从图片的 alt、文件名或正文附近内容推定交互。
- **无运行证据**：没有测试两图选择、不同尺寸、切换模式、缩放／拖动、支持格式或字段实际值；没有读取用户素材。

## 3. 媒体信息：字段与边界

官方详情显示 Media Info 1.0.2，页面版本记录日期 2025-04-02，读取音视频属性并嵌入右侧检查器；正文提到使用 MediaInfo.js。版本记录明确码率计算从二进制基数改为十进制基数，以符合 SI 单位。[S2]

**不能由这些资料确认：**

- 没有逐容器／逐编码的支持表；“音视频文件”不保证任意 MP4／MOV／WAV 内部变体都可解析。
- 没有说明多视频／多音轨时显示哪个、是否显示全部轨道；也未明确 VFR 帧率显示为平均值、范围或标识。
- 宽高、位深、像素格式、色彩原色、传递函数、HDR 元数据、编码 profile／level、声道布局等未在本轮已读正文中给出具体产品保证。
- 没有字段缺失／无效值／不支持格式的显示规范；读取耗时、取消、离线及过期结果处理也未公开。
- “采用 MediaInfo.js”没有给出插件内依赖版本、构建选项或完整包装逻辑，不能把上游库的全部能力转写成该插件能力；本轮不扩展调查该库或选择本产品实现。

对本产品而言，字段读取与播放能力应分别验收。读取出 HEVC 编码名称不证明该文件可播放，读取失败也不应令本来可用的基本播放功能失效；这是根据现有产品边界提出的衔接建议，不是 Eagle 的新事实。

## 6. 给人工决策和原型的建议（尚未采纳）

不需重问三个插件的选择。建议把剩余显示取舍拆成可直接看懂的场景：

1. **横图与竖图并排**：演示保持各自比例、完整画面和留白的候选；与裁满的结果对照，明确是否允许只通过缩放裁出视野。避免让用户把拉伸误当作原图差异。
2. **同构图、不同像素尺寸分割**：先决定按相同显示范围比较还是按原始像素比较；然后定义缩放倍率、中心点、是否同步和重置。需要解释选择的实际后果，不只问“要不要同步”。
3. **加载与不可用**：两图一侧离线／需要准备、一侧正常，以及打开后切换选择；不能让旧图或旧字段看起来属于新素材。
4. **参数缺失**：无 EXIF 的 PNG、无 GPS 的 JPEG、缺时区的拍摄时间、多轨音视频；让用户判断“缺字段”“不支持”“失败”是否能分清。
5. **方向与预览转换**：带旋转标记的照片、透明 PNG、已标记为 SDR 的预览。比较器应让用户知道看到的是哪种可用表示，不能把它当原字节或原始 HDR 的证明。

这些建议不扩大已选两图并排／滑杆范围，不自动加入叠加模式、照片修改、地图联网、颜色测量或额外格式。最终字段／格式清单与显示规则由37裁定，36验证理解，39结合所选运行方案验证实际行为。
